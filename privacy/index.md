# Didit 개인정보처리방침 (Privacy Policy)

**시행일: 2026년 10월 28일**

한국어 · [English](en/)

Didit(이하 "앱")을 만들고 운영하는 개인 개발자 남기훈(이하 "운영자")은 사용자의 개인정보와 데이터를 소중히 여기며, 「개인정보 보호법」 등 관련 법령과 Google Play 개발자 정책, Apple App Store 심사 지침을 준수합니다. 본 방침은 Didit Android 앱, iOS 앱(위젯 포함), macOS 앱(위젯 포함), Windows 데스크톱 앱과 Didit 웹사이트가 사용자의 정보를 어떻게 처리하고 보호하는지 설명합니다.

---

## 1. 처리하는 정보

Didit은 회원가입을 받지 않고, 광고 추적 식별자를 수집하지 않으며, 사용 통계·분석 도구와 광고를 사용하지 않습니다. 운영자의 서버에는 사용자의 할 일이나 계정 정보를 저장하지 않습니다.

### 1) 기기에 저장되는 데이터 (필수)
* **항목**: 사용자가 작성한 할 일 내용, 완료 일시, 알림·위젯·테마 등 앱 설정값, 기기별 무작위 식별자(동기화용, 아래 3번 참조)
* **보관 장소**: 사용자의 기기 내부 저장소 (Android: 앱 전용 데이터베이스, iOS·macOS: 앱과 Didit 위젯만 함께 쓰는 앱 전용 공유 저장소, Windows: `%LOCALAPPDATA%\Didit` 폴더)
* **외부 전송**: 클라우드 동기화를 켜지 않으면 앱이 할 일 데이터를 기기 밖으로 보내지 않습니다. 다만 사용자가 켠 운영체제의 기기 백업·이전 기능(Android의 Google 백업과 기기 간 이전, iPhone의 iCloud 백업과 기기 이전 등)에는 할 일과 설정이 포함될 수 있습니다. Google 로그인 정보는 이런 백업·이전에 포함되지 않습니다.
* **오류 기록**: 앱 오류 기록은 기기 안에만 저장되며 외부로 전송되지 않습니다.
* **Siri·단축어 (iOS)**: "Didit에 추가"로 할 일을 추가할 때 음성 인식은 Apple이 처리하며, 앱은 인식된 할 일 텍스트만 받아 기기에 저장합니다.

### 2) Google 계정 연결 및 클라우드 동기화 (선택)
사용자가 설정에서 Google 계정을 연결한 경우에만 처리합니다.
* **항목과 보관 장소**:
  * Google 계정 이메일 주소: 기기의 앱 설정에 보관합니다. 연결을 해제해도, 나중에 다른 계정에 연결할 때 기존 할 일을 지킬지 판단하려고 "이전 계정"으로 기기에 남으며, 앱을 삭제하면 함께 지워집니다.
  * 할 일 동기화 파일(`todonotification_backup.json`. 할 일과 마지막으로 올린 기기의 무작위 식별자를 담습니다)과 기기 접속 기록(기기마다 내용 없는 파일 하나. 파일 이름에 기기별 무작위 식별자와 기기 종류(Android, iOS, Windows, macOS)를 담고, 파일 수정 시각을 마지막 접속 시각으로 씁니다): 사용자 본인의 Google Drive 안에 있는 앱 전용 숨김 폴더(`appDataFolder`)에 보관합니다.
* **목적**: 여러 기기 간 할 일 동기화 및 백업. 기기 접속 기록은 같은 계정에 최근 사용한 다른 기기가 없을 때 실시간 동기화 신호(아래 3번)를 보내지 않기 위해서만 씁니다
* **접근 범위**: 앱은 사용자의 Drive 전체에 접근할 수 없으며, Didit이 만든 앱 전용 폴더에만 접근합니다. 요청하는 Google 권한은 앱 전용 폴더 접근(`https://www.googleapis.com/auth/drive.appdata`)과 로그인·계정 이메일 확인(`openid`, `email`)뿐입니다.
* **Google API 사용자 데이터 정책**: Didit이 Google API로 받은 정보를 사용하고 다른 앱으로 전송하는 방식은 [Google API 서비스 사용자 데이터 정책](https://developers.google.com/terms/api-services-user-data-policy)(제한적 사용 요건 포함)을 따릅니다. 이 정보는 할 일 동기화에만 쓰며, 광고에 쓰거나 판매하거나 제3자에게 넘기지 않고, 일반화된 인공지능·머신러닝 모델을 만들거나 개선하거나 학습시키는 데 쓰지 않습니다.
* **로그인 정보**: Google 로그인 인증 정보는 기기 안에만 보관됩니다 (Android: Google Play 서비스, iOS: 기기 키체인. 앱을 열지 않고 위젯·Siri에서 바로 동기화할 수 있도록 앱과 Didit 위젯이 함께 쓰며, 이 기기에서만 사용되고 백업이나 기기 이전으로 옮겨지지 않습니다. macOS: 기기 키체인, 앱만 사용. Windows: `%LOCALAPPDATA%\Didit\GoogleAuth` 폴더).

### 3) 실시간 동기화 알림
한 기기에서 할 일이 바뀌면 다른 기기가 바로 최신 내용을 받을 수 있도록 알림 신호를 보냅니다. **이 신호에는 할 일 내용이 포함되지 않습니다.** 신호는 Google 계정을 연결한 뒤에만 보내고 받습니다. 다만 Android·iOS 앱은 신호를 받을 준비로, 앱을 처음 실행할 때 아래 Firebase Cloud Messaging과 Apple 푸시 알림 서비스에 기기 등록 토큰을 만듭니다(계정이나 할 일은 담지 않습니다).
* **Didit 중계 서버 (Cloudflare Workers에서 운영)**
  * 전송 항목: 계정 이메일로 만든 해시 값(이메일 원문 아님), 기기별 무작위 식별자
  * 목적: 같은 계정의 다른 기기로 동기화 신호 전달
  * 보관: 저장하지 않습니다. 짧은 시간 내 중복 발송을 막기 위해 해시 값과 요청 시각을 수 초간 메모리에만 유지합니다. 요청 처리 과정에서 Cloudflare가 네트워크 정보(IP 주소 등)를 처리할 수 있습니다.
* **Firebase Cloud Messaging (Google, Android·iOS 앱)**
  * 처리 항목: 푸시 전달을 위한 기기 등록 토큰(Firebase 설치 ID, 앱을 처음 실행할 때 만듭니다), 위 해시 값으로 만든 구독 주제(계정을 연결한 뒤에 만듭니다). iOS에서는 Apple 푸시 알림 서비스(APNs)의 기기 토큰도 함께 처리합니다.
  * 목적: 중계 서버의 신호를 Android 기기와 iOS 기기(앱이 화면에 없을 때)에 전달. Android에서는 아무것도 표시하지 않습니다. iOS에서는 신호가 소리·진동 없는 알림으로 도착하고, 기기 안에서 동기화한 뒤 그 알림의 내용을 기기에 저장된 할 일로 채웁니다(신호 자체에는 할 일 내용이 없습니다). iOS 알림을 허용하지 않았다면 아무것도 표시하지 않고 동기화만 합니다.
* **Apple 푸시 알림 서비스 (Apple, iOS 앱)**
  * 처리 항목: 위 신호(할 일 내용 없음)와 APNs 기기 토큰
  * 목적: Firebase Cloud Messaging이 보낸 신호를 iOS 기기에 전달
* **Windows·macOS·iOS 앱의 신호 수신 (위 중계 서버)**
  * Windows 앱과 macOS 앱은 실행 중에, iOS 앱은 화면에 열려 있는 동안 중계 서버와 연결을 유지해 신호를 받습니다. iOS 앱이 화면에 없을 때는 위 푸시로 받습니다.
  * 연결 항목: 위 해시 값만 사용합니다. 이메일이나 기기 식별자는 연결에 사용하지 않습니다.
  * 보관: 연결 정보는 연결이 유지되는 동안 중계 서버 메모리에만 있고, 연결이 끊기면 사라집니다. 연결 중에 Cloudflare가 네트워크 정보(IP 주소 등)를 처리할 수 있습니다.

### 4) 앱 업데이트 확인
앱 화면을 열 때, 지금 버전을 계속 지원하는지 확인하려고 Didit 웹사이트(`hoonest.net`, GitHub Pages)에서 모든 사용자에게 똑같은 공개 파일 하나를 받습니다.
* **전송 항목**: 없습니다. 요청에 계정, 기기 식별자, 할 일 내용을 담지 않습니다.
* **목적**: 더 이상 지원하지 않는 옛 버전이면 업데이트를 안내
* **보관**: 앱은 받은 최소 버전 값만 기기 안에 저장합니다. 요청을 처리하는 과정에서 GitHub가 네트워크 정보(IP 주소 등)를 처리할 수 있습니다.

### 5) 웹사이트 방문
Didit 웹사이트(`hoonest.net`, `didit.hoonest.net`)는 회원가입, 입력 양식, 분석 도구, 광고를 두지 않습니다. 페이지를 전달하는 과정에서 호스팅 사업자(GitHub, Cloudflare)가 방문자의 네트워크 정보(IP 주소, 브라우저 정보 등)를 처리할 수 있습니다.

## 2. 처리 목적

처리하는 정보는 다음 목적으로만 이용합니다.
* 상시 알림, 홈 화면·잠금 화면·데스크톱 위젯, 메뉴 막대, 트레이, 컴팩트 바를 통한 할 일 표시
* 사용자가 요청한 여러 기기 간 Google Drive 동기화 및 백업
* 앱 설정값 유지
* 더 이상 지원하지 않는 옛 버전의 업데이트 안내

## 4. 제3자 제공 및 처리 위탁

Didit은 **사용자의 개인정보와 할 일 데이터를 제3자에게 제공하거나 판매, 대여하지 않습니다.** 동기화 파일은 사용자 본인의 Google 계정 공간에 사용자의 요청으로 저장됩니다.

앱 기능을 제공하기 위해 아래 사업자의 서비스를 이용합니다(처리 위탁). 모든 전송은 암호화된 연결(HTTPS)로 이루어집니다.

| 수탁자 | 서비스 | 위탁 업무 |
| :--- | :--- | :--- |
| Google LLC | Google Drive API, Google 로그인 | 사용자 Drive 앱 전용 폴더에 동기화 파일 저장, 계정 인증 |
| Google LLC | Firebase Cloud Messaging | Android·iOS 기기로 동기화 신호 전달 |
| Apple Inc. | Apple 푸시 알림 서비스(APNs) | iOS 기기로 동기화 신호 전달 (할 일 내용 없음) |
| Cloudflare, Inc. | Cloudflare Workers | 동기화 신호 중계 (할 일 내용 없음, 저장하지 않음), Didit 웹사이트 호스팅 |
| GitHub, Inc. | GitHub Pages | 앱 업데이트 확인용 공개 파일 제공, 웹사이트 호스팅 (계정·할 일 정보는 보내지 않으며, 요청을 처리하며 IP 주소 등 네트워크 정보만 처리) |

  * Android·iOS 앱이 처음 실행할 때 만드는 푸시 기기 등록 토큰(계정·할 일 없음), 앱 업데이트 확인과 웹사이트 방문에서 처리되는 IP 주소 등 네트워크 정보는 끄는 설정이 없습니다. 원하지 않으면 앱을 쓰지 않거나 삭제할 수 있으며, 네트워크를 끈 채 쓰면 업데이트 확인을 하지 않는 대신 지원이 끝난 버전이라는 안내를 받지 못합니다.

## 6. 이용자의 권리와 행사 방법

이용자는 언제든 자신의 개인정보를 열람, 정정, 삭제하거나 처리 정지를 요구할 수 있습니다. Didit의 데이터는 이용자의 기기와 본인 Google Drive에만 있으므로 대부분 직접 처리할 수 있습니다.
* **열람·정정**: 앱의 할 일 목록과 완료 목록에서 확인하고 고칠 수 있습니다.
* **기기 데이터 삭제**: 할 일을 영구 삭제하거나 앱을 삭제하면 기기에서 삭제됩니다.
* **처리 정지(동기화 해제)**: 앱의 [설정] → [Google 계정 연결 해제]로 언제든 동기화를 끌 수 있습니다. 해제해도 기기의 할 일은 유지되며, 해제 후에는 클라우드 동기화와 실시간 동기화 신호가 중단됩니다.
* **클라우드 데이터 삭제**: Google Drive 웹의 [설정] → [앱 관리]에서 Didit의 **숨겨진 앱 데이터 삭제**를 선택하면 Drive에 저장된 동기화 파일과 기기 접속 기록이 삭제됩니다.
* **Google 권한 철회**: [Google 계정 관리](https://myaccount.google.com/permissions) 페이지에서 언제든 Didit의 접근 권한을 취소할 수 있습니다.
* **요청**: 그 밖의 요청은 아래 11번 연락처로 보내 주시면 10일 이내에 답변합니다. 운영자는 이용자의 할 일이나 Drive 데이터에 접근할 수 없으므로, 그 데이터는 위 방법으로 직접 처리해 주셔야 합니다.

## 7. 개인정보의 안전성 확보 조치

* 모든 네트워크 전송은 HTTPS(TLS)로 암호화합니다.
* Google 권한은 앱 전용 폴더와 계정 이메일 확인으로 최소화하며, 사용자의 다른 Drive 파일에는 접근하지 않습니다.
* Google 로그인 정보는 운영체제가 제공하는 보안 저장소(키체인 등)나 앱 전용 폴더에만 보관하고, 백업으로 옮겨지지 않게 합니다.
* 이메일 원문은 운영자의 서버로 보내지 않으며, 동기화 신호에는 해시 값만 씁니다.
* 운영자의 서버에는 사용자의 할 일과 계정 정보를 저장하지 않습니다.
* 앱 오류 기록에는 할 일 내용, 계정 이메일, 인증 정보를 남기지 않습니다.
